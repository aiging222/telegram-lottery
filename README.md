# Telegram 可配置权重抽奖机器人

第一版使用 Python 3.11+、python-telegram-bot 和 SQLite，通过 Telegram 管理员命令配置。支持报名按钮（仅限发布群成员）、规则加成、个人权重覆盖、不重复抽奖、冻结快照及修改记录。

## 安装与启动

在本 README 所在目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock
python -m pip install --no-deps -e .
cp .env.example .env
```

也可以使用 [uv](https://docs.astral.sh/uv/)：执行 `uv sync` 按 `uv.lock` 创建 `.venv` 并安装项目和测试工具，再执行 `cp .env.example .env`。uv 创建的环境里没有 pip，下文命令改用 `uv run` 前缀，例如 `uv run python -m lottery.bot`。

如果项目位于 iCloud 同步的「文稿」或「桌面」目录，iCloud 会给 `.venv` 里的文件加上隐藏标记，Python 会跳过被隐藏的 `.pth` 文件，导致 `lottery-bot` 命令找不到 `lottery` 模块。解决办法是把环境建在 iCloud 不同步的 `venv.nosync` 目录，再用 `.venv` 链接过去：

```bash
uv venv venv.nosync
ln -s venv.nosync .venv
uv sync
```

使用 SOCKS 代理（例如 `ALL_PROXY=socks5://…`）时，依赖里已包含所需的 `python-telegram-bot[socks]`。

编辑本地 `.env`：

```dotenv
TELEGRAM_BOT_TOKEN=填写你的机器人令牌
ADMIN_USER_IDS=填写你的Telegram数字用户ID
DATABASE_PATH=data/lottery.sqlite3
```

- 通过 Telegram 官方 [@BotFather](https://t.me/BotFather) 创建机器人并获取令牌。令牌仅填写在本地 `.env`，不要提交到代码仓库。
- `ADMIN_USER_IDS` 是用户 ID，不是用户名、群 ID 或机器人的 ID；多个管理员用英文逗号分隔。
- 如果尚不知道自己的 ID，可临时将 `ADMIN_USER_IDS` 设为 `9223372036854775807`，启动后私聊机器人发送 `/id`，再将返回的真实 ID 填入配置并重启。这个临时值仅用于启动期间不授予实际用户管理权限；正式使用前必须替换。
- 在本目录运行；相对数据库路径以运行目录为基准。

```bash
python -m lottery.bot
```

启动后私聊机器人发送 `/help`。将机器人加入目标群，允许其发送消息，并设为群管理员：报名时机器人要向 Telegram 查询点击者是否在群内，Telegram 只保证管理员机器人能查到。管理员在群里执行 `/publish 抽奖ID` 即可发布带报名按钮的卡片。管理配置在私聊完成，`/publish` 和 `/draw` 可在群里执行；群里如有多个机器人，可使用 `/publish@你的机器人用户名 1`。

当前使用长轮询，不需要公网 Webhook 地址。运行机器需要能访问 Telegram；同一令牌只运行一个轮询进程。停止进程后机器人不再响应，恢复运行后从数据库继续。此交付未配置服务器常驻部署。

## 群成员能看到什么

权重配置、完整名单预览和导出，只接受管理员在与机器人的私聊中操作；机器人不会将这些配置操作转发到群里。若你主动将配置指令发到群里，原始消息本身仍会被群成员看到，机器人拒绝执行并不等于消息被隐藏或撤回。

群内可见内容包括报名公告、公开的权重规则和开奖结果。成员可以查询自己的权重；群卡片的“查看我的权重”按钮以个人弹窗答复，不向整个群发送查询结果。成员不能使用预览或导出命令查询全体名单和管理记录。

## 一次完整操作

先在管理员与机器人的私聊中发送：

```text
/new 3 60 周末抽奖
```

表示创建抽取 3 人、60 分钟后截止的抽奖。机器人返回实际抽奖 ID，下面以 `1` 为例；用户 ID `123456789` 也需要替换为实际值。

```text
/config 1 1 100
/rule 1 vip 2
/rule 1 task_done 3
/grant 1 123456789 vip
/weight 1 123456789 10
/preview 1
```

然后在目标群发送：

```text
/publish 1
```

首次在群里 `/publish` 会把抽奖绑定到该群，之后只有该群的当前成员能报名。绑定后不能再发布到其他群（开奖结果不受限制）；发错群时请新建抽奖。普通群升级为超级群后群 ID 会变，机器人会自动跟随。

参与者点击“报名”。到截止时间后，在需要公布结果的聊天发送：

```text
/draw 1
```

如需提前结束，先私聊发送 `/freeze 1`，再开奖。冻结不可撤销。结果会保存在数据库中，重复 `/draw 1` 或断网后重试会返回相同结果；可能重复发送公告，但不会重新抽取中奖人。

## 命令表

| 命令 | 用途 | 权限/位置 |
| --- | --- | --- |
| `/help` | 使用说明 | 所有人 |
| `/id` | 查询自己的用户 ID | 所有人 |
| `/raffle ID` | 查询抽奖和当前报名按钮 | 所有人 |
| `/rules ID` | 查询全部规则 | 所有人 |
| `/myweight ID` | 查询自己的权重和首轮概率 | 私聊；群卡片也有私人弹窗按钮 |
| `/result ID` | 查询已保存的结果 | 所有人 |
| `/new 名额 分钟数 标题` | 创建活动 | 管理员私聊 |
| `/config ID 默认权重 上限` | 调整全局权重参数 | 管理员私聊 |
| `/rule ID 规则名 加成` | 创建或更新规则；设为 0 可停用加成 | 管理员私聊 |
| `/grant ID 用户ID 规则名` | 授予某项条件，重复授予不叠加 | 管理员私聊 |
| `/revoke ID 用户ID 规则名` | 撤销某项条件 | 管理员私聊 |
| `/weight ID 用户ID 数值` | 设置最终个人权重 | 管理员私聊 |
| `/weight ID 用户ID auto` | 取消个人覆盖，恢复规则计算 | 管理员私聊 |
| `/preview ID` | 预览前 30 人权重、来源和首轮概率 | 管理员私聊 |
| `/export ID` | 导出完整 JSON、快照、结果和修改记录 | 管理员私聊 |
| `/freeze ID` | 提前停止报名并冻结权重，不可撤销 | 管理员私聊 |
| `/draw ID` | 截止或冻结后开奖，在当前聊天公布 | 管理员 |
| `/publish ID` | 发布报名卡片，首次在群里发布时绑定该群；已开奖则发布结果 | 管理员 |
| `/raffles` | 最近 20 场活动 | 管理员私聊 |

## 权重与开奖规则

```text
有个人覆盖值：最终权重 = 个人覆盖值
无个人覆盖值：最终权重 = min(默认权重 + 已授予的规则加成之和, 权重上限)
```

- 所有权重均为非负整数，上限最大 1,000,000。个人覆盖值也不能超过本场上限。
- 权重 `0` 表示不参与抽取；`auto` 表示取消覆盖，两者不同。
- 可以在报名之前按用户 ID 设置权重或授予条件；这些操作不会替用户报名。
- 一人同一规则最多生效一次；不同规则加成相加。
- 更新规则会影响所有拥有该条件的参与者，个人覆盖值仍然优先。
- 比如权重为 1、3、6，首轮概率分别为 10%、30%、60%。每抽出一人就移除该人，再按剩余权重抽下一人。
- 多名中奖者的最终中奖概率不能直接用首轮概率乘以名额。
- 名额支持 1～100；正权重人数不足时抽取全部符合条件者，并在公告说明实际人数；无有效参与者时保存“0 人中奖”的结果。
- 抽奖彼此独立，不共享个人覆盖或已授予条件。

## 截止、快照与数据

到截止时刻，即使机器人曾离线，任何新的报名、规则修改和个人权重修改都会被拒绝。到期后首次读取或开奖时写入冻结快照；也可以提前 `/freeze`。本版由管理员 `/draw` 开奖，不会到点自动发送公告。

采用 SQLite `BEGIN IMMEDIATE` 事务串行化写入。快照、结果和开奖记录一起提交；并发开奖只能提交一份结果。随机抽取使用 Python `secrets.randbelow`，按整数权重划分区间，无浮点随机边界问题。

每次管理操作保存操作人、时间和变更内容；规则、默认配置、个人覆盖保存修改前后值。重复授予已有条件、撤销不存在的条件不产生记录，机器人会回复“未做修改”。冻结快照包括参与名单、规则、个人权重和计算结果，SHA-256 摘要用于检查快照是否一致。摘要不是公开可验证的随机性证明，数据库文件本身也不是防管理员篡改的审计系统。

数据库默认保存在 `data/lottery.sqlite3`。迁移或备份时先停止机器人，再复制数据库文件及配置。不要删除数据库后期待找回历史结果。

表结构版本记录在 SQLite 的 `PRAGMA user_version` 中。机器人启动时按顺序执行 `lottery/core.py` 里 `MIGRATIONS` 列表中尚未执行的迁移，全部在同一个事务内完成，失败则整体回滚。修改表结构时只在列表末尾追加新迁移，不要改动已发布的迁移。升级前建议先备份数据库文件。

## 第一版范围

- 条件由管理员核验后使用 `/grant` 授予；尚未接入自动验证入群、邀请数、付费或任务完成情况。
- 报名仅限发布群的当前成员：每次点击报名都通过 Telegram `getChatMember` 实时查询，查询失败时拒绝报名。只在报名时检查，报名后退群不会取消资格；不提供多账号识别。
- 配置中的管理员可管理所有抽奖，群管理员身份不会自动获得机器人管理权限。
- 支持私聊和群聊；不提供频道内匿名管理命令流程。
- 报名卡片的人数和规则是发布时数据，不自动刷新；`/raffle`、`/rules` 和权重查询读取当前数据，旧报名按钮在截止后也会拒绝报名。
- 不自动发奖，不处理资金，不提供重新抽奖或撤销开奖命令。

## 离线演示与测试

不需要 Telegram 令牌即可运行演示：

```bash
python -m lottery.demo
```

演示在临时数据库创建权重为 1、3、6、0 的四人抽奖，冻结并抽取两人，再验证重复开奖结果相同。

```bash
python -m pip install -e '.[dev]'
python -m pytest -q
ruff check .
ruff format --check .
```

使用 uv 时无需单独安装，直接执行 `uv run pytest -q`、`uv run ruff check .`、`uv run ruff format --check .`。

测试覆盖抽取区间、无重复中奖、零权重、覆盖恢复、规则叠加、截止边界、权限、群成员校验与群绑定、并发报名/开奖、重启恢复及公告失败后的重试。Telegram 收发通过模拟对象测试；真实机器人联调需要本地填写令牌后执行。

接口实现参考 [Telegram Bot API](https://core.telegram.org/bots/api) 和 [python-telegram-bot 官方文档](https://docs.python-telegram-bot.org/en/stable/)。生产运行依赖已锁定在 `requirements.lock`（pip 使用），完整依赖另锁定在 `uv.lock`（uv 使用），两者都由 `pyproject.toml` 生成。修改依赖后需重新生成两份锁文件：

```bash
uv lock
uv pip compile pyproject.toml -o requirements.lock
```
