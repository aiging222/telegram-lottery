# Telegram 可配置权重抽奖机器人

使用 Python 3.11+、python-telegram-bot 和 SQLite。群管理员在私聊里用按钮发起和管理本群抽奖（定时开奖或满人开奖）；超级管理员另可用命令配置权重（规则加成、个人权重覆盖）。支持报名按钮（仅限发布群成员）、不重复抽奖、冻结快照及修改记录。

## 安装与启动

在本 README 所在目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock
python -m pip install --no-deps -e .
cp .env.example .env
```

也可以使用 [uv](https://docs.astral.sh/uv/)：执行 `uv sync` 按 `uv.lock` 创建 `.venv` 并安装项目和测试工具，再执行 `cp .env.example .env`。uv 创建的环境里没有 pip，下文命令改用 `uv run` 前缀，例如 `uv run python -m lottery.bot`。

如果项目位于 iCloud 同步的「文稿」或「桌面」目录，iCloud 会给 `.venv` 里的文件加上隐藏标记，Python 会跳过被隐藏的 `.pth` 文件，导致 `lottery-bot` 命令找不到 `lottery` 模块。解决办法是把环境建在 iCloud 不同步的 `venv.nosync` 目录，再用 `.venv` 链接过去：

```bash
uv venv venv.nosync
ln -s venv.nosync .venv
uv sync
```

使用 SOCKS 代理（例如 `ALL_PROXY=socks5://…`）时，依赖里已包含所需的 `python-telegram-bot[socks]`。

编辑本地 `.env`：

```dotenv
TELEGRAM_BOT_TOKEN=填写你的机器人令牌
ADMIN_USER_IDS=填写你的Telegram数字用户ID
DATABASE_PATH=data/lottery.sqlite3
TIMEZONE=Asia/Shanghai
```

- 通过 Telegram 官方 [@BotFather](https://t.me/BotFather) 创建机器人并获取令牌。令牌仅填写在本地 `.env`，不要提交到代码仓库。
- `ADMIN_USER_IDS` 是用户 ID，不是用户名、群 ID 或机器人的 ID；多个管理员用英文逗号分隔。
- 如果尚不知道自己的 ID，可临时将 `ADMIN_USER_IDS` 设为 `9223372036854775807`，启动后私聊机器人发送 `/id`，再将返回的真实 ID 填入配置并重启。这个临时值仅用于启动期间不授予实际用户管理权限；正式使用前必须替换。
- 在本目录运行；相对数据库路径以运行目录为基准。
- `TIMEZONE` 填 IANA 时区名（如 `Asia/Shanghai`、`America/New_York`），只影响报名卡片上截止时间的显示，并会自动处理夏令时；不填时默认 `Asia/Shanghai`。截止判断本身与时区无关。

```bash
python -m lottery.bot
```

启动后私聊机器人发送 `/start`，点「➕ 添加到群组」选择目标群，并把机器人设为群管理员：报名时机器人要向 Telegram 查询点击者是否在群内，成员退群时也要收到通知，这两件事 Telegram 只对管理员机器人保证。机器人进群后会发一条带「⚙️ 管理抽奖」按钮的欢迎消息，之后在群里发送 `/start` 也会再发一条。

机器人如果是在本版本之前进的群，菜单里还没有这个群：在群里发一次 `/start` 即可登记。

当前使用长轮询，不需要公网 Webhook 地址。运行机器需要能访问 Telegram；同一令牌只运行一个轮询进程。停止进程后机器人不再响应，恢复运行后从数据库继续。此交付未配置服务器常驻部署。

## 谁能做什么

| 身份 | 能做的事 |
| --- | --- |
| 超级管理员（`.env` 的 `ADMIN_USER_IDS`） | 管理所有群的抽奖；独有权重配置、`/rules`、预览、导出等命令 |
| 群管理员（群主或管理员） | 在私聊菜单里发起、截止、开奖、取消、重新发布**本群**的抽奖 |
| 群成员 | 点卡片上的「🎟 参与抽奖」报名，查看卡片和开奖结果 |

群管理员身份每次都向 Telegram 实时查询（结果缓存 60 秒），查询失败时一律按“不是管理员”处理。被撤销管理员后最多 60 秒失去权限。

## 群成员能看到什么

权重只有超级管理员能看到和修改。设置过规则加成或个人权重的抽奖，卡片上只显示「本场设有中奖加成」，不公布具体规则、谁有加成或任何人的权重；成员也不能查询自己的权重。

权重配置、完整名单预览和导出，只接受超级管理员在与机器人的私聊中操作；机器人不会将这些配置操作转发到群里。若你主动将配置指令发到群里，原始消息本身仍会被群成员看到，机器人拒绝执行并不等于消息被隐藏或撤回。

群内可见内容包括报名卡片（奖品、中奖人数、已参与人数、开奖时间或满人条件）、开奖结果和取消通知。开奖结果会 @ 中奖者，点名字可直接打开对方资料。

## 用按钮发起抽奖（群管理员）

1. 在群里点欢迎消息的「⚙️ 管理抽奖」，或私聊机器人 `/start` →「📋 我的群」，进入该群菜单。菜单显示进行中、已开奖、已取消的场数。
2. 点「➕ 发起抽奖」，按提示依次：发送奖品名称 → 选中奖人数 → 选开奖方式 → 选开奖时间或满多少人。每一步都可点「其他」自己输入：人数输入整数；时间可输入 `90分钟`、`2小时`、`3天`、`45`（分钟），或 `2026-10-05 20:00`、`10-05 20:00`（按 `TIMEZONE` 解读）。
   - **定时开奖**：到时间自动开奖。
   - **满人开奖**：报名人数达到设定值时立即开奖；7 天内没满也会在第 7 天自动开奖。
3. 确认摘要后点「✅ 发布到群」，报名卡片直接发到群里。未完成的填写保存在数据库里，机器人重启后接着填；点「✖ 取消」放弃。
4. 「📜 抽奖记录」列出本群所有抽奖，点进一场可以：
   - 🎲 立即开奖：截止报名并开奖，结果发到群里；
   - ⏹ 截止报名：不再接受报名，到原定时间自动开奖；
   - ✖ 取消抽奖：未开奖的抽奖可以取消，群里会收到通知，卡片改为「已取消」，不可恢复；
   - 📣 重新发布：卡片被刷到上面或误删时，再发一张（仅报名中）。

这三个操作都要再点一次「✅ 确定」。群卡片上的参与人数会在有人报名后几秒内自动更新，开奖、截止、取消后按钮自动消失。

## 用命令配置权重（超级管理员）

按钮发起的抽奖默认人人权重相同。需要加权时，在记录里看到抽奖 ID（标题后的 `#数字`），私聊用下文命令配置即可。也可以完全用命令创建和发布：

先在超级管理员与机器人的私聊中发送：

```text
/new 3 60 周末抽奖
```

表示创建抽取 3 人、60 分钟后截止的抽奖。机器人返回实际抽奖 ID，下面以 `1` 为例；用户 ID `123456789` 也需要替换为实际值。

```text
/config 1 1 100
/rule 1 vip 2
/rule 1 task_done 3
/grant 1 123456789 vip
/weight 1 123456789 10
/preview 1
```

然后在目标群发送：

```text
/publish 1
```

首次在群里 `/publish` 会把抽奖绑定到该群，之后只有该群的当前成员能报名。绑定后不能再发布到其他群（开奖结果不受限制）；发错群时请新建抽奖。普通群升级为超级群后群 ID 会变，机器人会自动跟随。

参与者点击「🎟 参与抽奖」。**到截止时间后不需要任何操作**：机器人每 30 秒检查一次，会在截止后半分钟内自动开奖，并把结果发到发布群。

如需提前结束，先私聊发送 `/freeze 1` 截止报名（不可撤销），再发送 `/draw 1` 立即开奖；也可以只截止报名，等到原定时间自动开奖。每场抽奖的结果只在发布群公布一次：在发布群里手动 `/draw` 后不会再自动发送；在私聊里 `/draw` 的结果会在半分钟内自动补发到发布群。结果保存在数据库中，重复 `/draw 1` 或断网后重试都返回相同结果，不会重新抽取中奖人。

## 权重与开奖规则

```text
有个人覆盖值：最终权重 = 个人覆盖值
无个人覆盖值：最终权重 = min(默认权重 + 已授予的规则加成之和, 权重上限)
```

- 所有权重均为非负整数，上限最大 1,000,000。个人覆盖值也不能超过本场上限。
- 权重 `0` 表示不参与抽取；`auto` 表示取消覆盖，两者不同。
- 可以在报名之前按用户 ID 设置权重或授予条件；这些操作不会替用户报名。
- 一人同一规则最多生效一次；不同规则加成相加。
- 更新规则会影响所有拥有该条件的参与者，个人覆盖值仍然优先。
- 比如权重为 1、3、6，首轮概率分别为 10%、30%、60%。每抽出一人就移除该人，再按剩余权重抽下一人。
- 多名中奖者的最终中奖概率不能直接用首轮概率乘以名额。
- 名额支持 1～100；正权重人数不足时抽取全部符合条件者，并在公告说明实际人数；无有效参与者时保存“0 人中奖”的结果。
- 抽奖彼此独立，不共享个人覆盖或已授予条件。

## 截止、快照与数据

到截止时刻，即使机器人曾离线，任何新的报名、规则修改和个人权重修改都会被拒绝。到期后首次读取或开奖时写入冻结快照；也可以提前 `/freeze`。

已在群里发布的抽奖到截止时间自动开奖，满人开奖的抽奖在最后一人报名成功时立即开奖，结果都发到发布群；名额满后再点报名会提示“名额已满”。从未发布到群的抽奖没有人能报名，不会自动开奖，需要时可手动 `/draw`。公告发送失败会在下一轮重试；机器人已被移出群等无法发送的情况会记录日志并停止重试，结果仍可用 `/result` 查询。升级到这个版本时已经过了截止时间的抽奖不会被自动补发公告。

采用 SQLite `BEGIN IMMEDIATE` 事务串行化写入。快照、结果和开奖记录一起提交；并发开奖只能提交一份结果。随机抽取使用 Python `secrets.randbelow`，按整数权重划分区间，无浮点随机边界问题。

每次管理操作保存操作人、时间和变更内容；规则、默认配置、个人覆盖保存修改前后值。重复授予已有条件、撤销不存在的条件不产生记录，机器人会回复“未做修改”。冻结快照包括参与名单、规则、个人权重和计算结果，SHA-256 摘要用于检查快照是否一致。摘要不是公开可验证的随机性证明，数据库文件本身也不是防管理员篡改的审计系统。

数据库默认保存在 `data/lottery.sqlite3`。迁移或备份时先停止机器人，再复制数据库文件及配置。不要删除数据库后期待找回历史结果。

表结构版本记录在 SQLite 的 `PRAGMA user_version` 中。机器人启动时按顺序执行 `lottery/core.py` 里 `MIGRATIONS` 列表中尚未执行的迁移，全部在同一个事务内完成，失败则整体回滚。修改表结构时只在列表末尾追加新迁移，不要改动已发布的迁移。升级前建议先备份数据库文件。

## 第一版范围

- 条件由管理员核验后使用 `/grant` 授予；尚未接入自动验证入群、邀请数、付费或任务完成情况。
- 报名仅限发布群的当前成员：每次点击报名都通过 Telegram `getChatMember` 实时查询，查询失败时拒绝报名。
- 名单冻结前（截止或 `/freeze`）退群、被踢出或被封禁，会自动取消报名并记入修改记录；重新入群后可以再次报名。以退群发生的时间为准：机器人离线期间的退群，只要发生在截止前、且名单尚未冻结，恢复运行后仍会生效。名单冻结后退群不影响开奖。Telegram 最多保留 24 小时内的更新，离线更久可能漏掉退群事件。
- 不提供多账号识别。
- 群管理员只能通过按钮管理本群抽奖，不能配置权重；权重相关操作只开放给 `ADMIN_USER_IDS` 里的超级管理员。
- 支持私聊和群聊；不提供频道内匿名管理命令流程。
- 群卡片由机器人自动编辑更新；重新发布后只更新最新一张，旧卡片的按钮在截止后仍会拒绝报名。
- 不自动发奖，不处理资金。未开奖的抽奖可以取消；已开奖的不能重新抽奖或撤销。

```bash

```

测试覆盖抽取区间、无重复中奖、零权重、覆盖恢复、规则叠加、截止边界、权限、群成员校验与群绑定、退群取消报名、时区显示、到点自动开奖与群公告、满人开奖、取消、按钮菜单（创建向导、群管理员权限、记录操作、进群欢迎）、并发报名/开奖、重启恢复及公告失败后的重试。Telegram 收发通过模拟对象测试；真实机器人联调需要本地填写令牌后执行。

接口实现参考 [Telegram Bot API](https://core.telegram.org/bots/api) 和 [python-telegram-bot 官方文档](https://docs.python-telegram-bot.org/en/stable/)。生产运行依赖已锁定在 `requirements.lock`（pip 使用），完整依赖另锁定在 `uv.lock`（uv 使用），两者都由 `pyproject.toml` 生成。修改依赖后需重新生成两份锁文件：

```bash
uv lock
uv pip compile pyproject.toml -o requirements.lock
```
